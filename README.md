## 1. Project Overview

The **Cybersecurity Incident Correlation & Response Intelligence System** is an enterprise-grade Security Operations Center (SOC) intelligence platform designed to eliminate the critical bottleneck of **lexical divergence** in cyber threat management. 

When diverse intrusion detection systems (IDS), firewalls, and security analysts log incidents, they describe the same attack taxonomy with distinct wording (e.g., *"phishing credential harvester"* vs. *"stolen Microsoft 365 credentials via deceptive login page"*). Standard relational keyword search (`LIKE %keyword%`) completely fails to correlate these threats.

This system solves this challenge by implementing a unified **Dual-Paradigm Database Architecture** in **PostgreSQL 15**:
- **Relational SQL Core**: 11 normalized tables (3NF/BCNF) enforcing domain integrity, cascade policies, forensic audit logs, stored risk functions, triggers, and multi-table ACID transactions.
- **Dense Vector Retrieval Engine**: Integrated `pgvector` extension storing 384-dimensional dense vectors generated by Hugging Face `all-MiniLM-L6-v2`, indexed via Hierarchical Navigable Small World (**HNSW**) graphs with sub-millisecond Cosine Distance (`<=>`) matching.

## 4. System Architecture & Relational Schema

### Database Entity Model (11 Normalized Tables)
1. **`roles`**: System permission tiers (`Administrator`, `Security Analyst`).
2. **`users`**: SOC staff members with bcrypt password hashes, email check constraints, and `reports_to` self-referencing supervisor foreign key.
3. **`assets`**: Critical corporate IT assets (Databases, Servers, Firewalls, Clusters, Cloud Storage).
4. **`incident_types`**: Attack taxonomy (Phishing, Ransomware, SQLi, DDoS, Zero-Day Exploit, etc.).
5. **`incidents`**: Central entity recording title, narrative, severity, priority, status, and calculated risk score.
6. **`investigations`**: Forensic findings, memory analysis, reverse shell artifacts, and analyst notes.
7. **`response_actions`**: Mitigation and containment actions (Firewall drop, network quarantine, snapshot recovery).
8. **`incident_status_history`**: Automated status lifecycle tracking populated by database trigger.
9. **`risk_assessments`**: Quantitative multi-factor evaluation records.
10. **`audit_logs`**: Immutable security event logs.
11. **`incident_embeddings`**: 384-dimensional dense vectors indexed via HNSW graph in `pgvector`.

## 5. Advanced DBMS Features Implemented

### 5.1 Stored Functions (Quantitative Risk Scoring)
- **File**: `database/functions/01_calculate_incident_risk.sql`
- **Formula**:
  $$\text{Risk Score} = 0.40 \cdot \text{Severity} + 0.35 \cdot \text{Asset Criticality} + 0.25 \cdot \text{Impact Score}$$
- Categorizes scores into discrete tiers: `LOW` (0–25), `MEDIUM` (26–50), `HIGH` (51–75), `CRITICAL` (76–100).

### 5.2 Database Trigger (Forensic Status Auditing)
- **File**: `database/triggers/02_incident_status_trigger.sql`
- **Trigger**: `trg_incident_status_change` fires `BEFORE UPDATE OF status ON incidents`.
- Automatically logs state transition into `incident_status_history` and `audit_logs`.
- Automatically sets `resolved_at = CURRENT_TIMESTAMP` upon resolution and clears it if reopened.

### 5.3 ACID Stored Procedure (Incident Assignment)
- **File**: `database/transactions/03_incident_assignment_transaction.sql`
- **Procedure**: `sp_assign_incident_atomic(incident_id, analyst_id, admin_id, notes)`.
- Validates incident existence, verifies analyst role, updates status to `'Investigating'`, and logs audit record. Any failure triggers automatic rollback, ensuring zero partial state.

### 5.4 14 Complex Analytical Queries
- **File**: `database/queries/05_complex_analytical_queries.sql`
- Covers multi-table joins, conditional aggregations (`CASE WHEN`), scalar subqueries, correlated subqueries (`Q13`: identifying incidents exceeding attack type average), and recursive CTEs (`Q14`: multi-level SOC supervisor-to-analyst escalation hierarchy).

## 7. Setup & Execution Instructions

### Prerequisites
- Node.js v18+ (Verified on v22.19.0)
- Python 3.10+ (Verified on Python 3.12.8 with `sentence-transformers`, `torch`, and `psycopg2`)
- PostgreSQL 14+ with `pgvector` extension enabled on port 5432 (Database: `cybersecurity_db`, user: `postgres`, password: `2233`)

### Installation & Run
```bash

npm install

# 2. Start Next.js Development Server
npm run dev

# 3. Access Web Application
# Open browser at: http://localhost:3000
```
